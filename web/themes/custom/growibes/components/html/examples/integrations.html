02 / The real problem

Integration is not connecting two APIs. It's designing the behavior between them.

Enterprise ecosystems rarely have one source of truth. They have several systems, each authoritative for a different part of the business. The engineering challenge is deciding where truth lives, how it travels, what happens when it fails and which system is allowed to change what.

Drupal's API-first initiative is explicitly designed to expose content over HTTP APIs, support new integrations and enable progressively or fully decoupled experiences.

03 / The hidden tax

Most integration debt begins with “just connect it.”

A quick connector can solve today's demo while creating tomorrow's operating problem. Enterprise integration needs ownership, contracts, failure handling and observability from the start.

01

Two systems disagree.

Without explicit ownership, the integration becomes a negotiation every time data changes.

02

One system goes down.

Resilience means defining queues, retries, fallbacks and reconciliation — not hoping the network behaves.

03

Data changes shape.

Contracts, validation and transformation protect the receiving system from upstream surprises.

04

Nobody can see the flow.

Observability turns “something is broken” into a traceable event with an owner and recovery path.

05 / Integration architecture

Don't build
spaghetti.

Strong integration architecture makes boundaries explicit: who owns data, who consumes it, how it travels and what happens when a dependency disappears.

LAYER 01

Experience

Web, portals, apps and digital products consume stable contracts instead of reaching into internal systems.

LAYER 02

Drupal domain

Content, editorial state, taxonomy, permissions and domain logic remain owned by the system responsible for them.

LAYER 03

API / event boundary

REST, JSON:API, GraphQL where appropriate, webhooks and events create deliberate seams between systems.

LAYER 04

Enterprise services

CRM, ERP, PIM, DAM, identity, commerce and data platforms remain independently operable.

LAYER 05

Operations

Monitoring, logging, retries, rate limits, secrets, queues and reconciliation make the ecosystem observable.

06 / The pattern

Connect less.
Coordinate better.

01 / DEFINE

Ownership.

Identify the authoritative system for every critical data object.

02 / CONTRACT

Shape.

Define schemas, authentication, validation and versioning before implementation.

03 / MOVE

Transport.

Choose synchronous APIs, events, queues or batch processes based on business behavior.

04 / OBSERVE

Recover.

Make failures visible, retryable and reconcilable rather than mysterious.

07 / Enterprise discipline

An integration is only successful if the business can trust it.

Security, reliability and operational ownership are part of the interface — not cleanup after the connector works.

AUTH
Identity belongs at the boundary.

Use appropriate authentication and authorization patterns rather than passing trust through the ecosystem.

RESILIENCE
Assume dependencies will fail.

Retries, queues, timeouts and fallbacks should be designed around the business impact of failure.

OBSERVABILITY
Every critical flow needs a trace.

Logs, metrics and correlation identifiers make cross-system failures diagnosable.

DATA
Move only what the system needs.

Minimize duplication and make transformations explicit so sensitive or stale data does not spread unnecessarily.

CHANGE
Contracts should survive evolution.

Version APIs and integration behavior so one team's release does not become another team's outage.

08 / Market reality

Drupal is built to be connected.

Drupal's API-first architecture is specifically intended to make content available to other software, enable new integrations and support decoupled experiences. Current enterprise implementations continue to push Drupal as a high-performance API and omnichannel content layer.

API-FIRST
Drupal exposes content as an integration capability.

Core's API-first initiative explicitly supports integrations, full decoupling and progressive decoupling through HTTP APIs.

OMNICHANNEL
One content source can power many experiences.

Drupal's technical positioning emphasizes structured content and API-first delivery across web, mobile and other channels.

ENTERPRISE
Integration architecture is a scale problem, not just a connector problem.

Real enterprise headless case studies highlight API performance, caching, indexing, rate limiting, security and reliability as part of the architecture.
