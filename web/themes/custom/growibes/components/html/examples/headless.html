Headless is not the product.
Freedom to evolve the experience without rebuilding the content system is.

Drupal was designed around an API-first direction: content can be exposed over HTTP, supporting integrations, progressive decoupling and full decoupling.

That means the architecture decision is not “headless or not.” It is: where should separation create measurable value?

01 / The trigger

Your channels changed.
Your CMS shouldn't become the bottleneck.

02 / Architecture judgment

Don't decouple for fashion.
Decouple for leverage.

01 / UNIFIED

Drupal renders.

Best when editorial speed, governance, SEO and a single web experience matter more than frontend independence.

Use simplicity as an advantage
02 / PROGRESSIVE

Drupal + focused JS.

Keep the editorial foundation while introducing React or other JavaScript experiences exactly where richer interaction earns its complexity.

Separate only what needs separation
03 / FULLY DECOUPLED

Drupal becomes the core.

Use an API-first backend when multiple channels, application-grade experiences or independent frontend delivery justify a full separation.

Build freedom into the platform
03 / The operating model

Separate the layers.
Strengthen the system.

A serious headless build is more than a frontend swap. Content modeling, API contracts, routing, authentication, preview, caching, observability and deployment all have to agree.

Experience
Next.js / React / Vue / mobilePerformance, interaction, accessibility, experimentation and channel-specific UX.
Contract
JSON:API / GraphQL / RESTPredictable schemas, versioning, documentation and deliberate exposure of content.
Content core
Drupal entities + editorial workflowsStructured content, relationships, moderation, media, taxonomy and permissions.
Trust layer
Identity / auth / caching / observabilityCORS, OAuth/JWT patterns, cache strategy, logging and failure visibility.
Delivery
CI/CD + environments + infrastructurePreview, automated tests, release discipline and operational ownership.
04 / What we actually engineer

A platform your next channel can inherit.

Content architecture

Frontend freedom
